═══════════════════════════════════════════════════════
PROJECT OVERVIEW
═══════════════════════════════════════════════════════
System name    : WMS — Warehouse Management System (仓库管理系统)
Core purpose   : Users upload order sheets (Excel / CSV / PDF) to
                 automatically trigger stock-in (入库) or stock-out (出库),
                 update inventory records, and view real-time statistics
                 including quantity, unit price, and total asset value.

═══════════════════════════════════════════════════════
TECH STACK
═══════════════════════════════════════════════════════
Backend
  Runtime    : Node.js 20 + Express 4 + TypeScript
  ORM        : Prisma 5  (SQLite for dev, PostgreSQL-compatible schema)
  Auth       : JWT — access token 15 min + refresh token 7 days
  Validation : Zod (schemas shared with frontend via /shared)
  File upload: Multer  (accept .xlsx .xls .csv .pdf)
  Parsing    : SheetJS/xlsx  for Excel & CSV
               pdf-parse     for PDF
  Logging    : Winston

Frontend
  Framework  : React 18 + TypeScript + Vite 5
  UI library : Tailwind CSS 3 + shadcn/ui
  State      : Zustand 4
  Data fetch : Axios + TanStack React Query v5
  Charts     : Recharts 2
  File parse : SheetJS (client-side preview before upload)

  Implement ALL models below exactly:

  model User {
    id           String   @id @default(cuid())
    username     String   @unique
    email        String   @unique
    passwordHash String
    role         Role     @default(OPERATOR)
    createdAt    DateTime @default(now())
    updatedAt    DateTime @updatedAt
    transactions Transaction[]
  }

  enum Role { ADMIN OPERATOR VIEWER }

  model Product {
    id            String   @id @default(cuid())
    sku           String   @unique
    name          String
    category      String
    unit          String
    unitPrice     Decimal
    description   String?
    minStockLevel Int      @default(10)
    createdAt     DateTime @default(now())
    updatedAt     DateTime @updatedAt
    inventory     Inventory?
    transactions  Transaction[]
  }

  model Inventory {
    id                String   @id @default(cuid())
    productId         String   @unique
    product           Product  @relation(fields: [productId], references: [id])
    warehouseLocation String   @default("A-01")
    currentQuantity   Int      @default(0)
    reservedQuantity  Int      @default(0)
    lastUpdatedAt     DateTime @updatedAt
  }

  model Transaction {
    id          String          @id @default(cuid())
    type        TransactionType
    productId   String
    product     Product         @relation(fields: [productId], references: [id])
    quantity    Int
    unitPrice   Decimal
    totalAmount Decimal
    operator    String
    userId      String?
    user        User?           @relation(fields: [userId], references: [id])
    note        String?
    sourceFile  String?
    batchId     String?
    createdAt   DateTime        @default(now())
  }

  enum TransactionType { STOCK_IN STOCK_OUT ADJUSTMENT }

  model UploadRecord {
    id           String   @id @default(cuid())
    filename     String
    originalName String
    fileType     String
    fileSize     Int
    status       String
    parsedRows   Int      @default(0)
    successRows  Int      @default(0)
    failedRows   Int      @default(0)
    errorLog     String?
    uploadedBy   String
    createdAt    DateTime @default(now())
  }

═══════════════════════════════════════════════════════
EXCEL UPLOAD TEMPLATE FORMAT
═══════════════════════════════════════════════════════
The system must accept Excel/CSV files with these columns
(support both Chinese and English headers):

| SKU      | 品名     | 数量     | 单价      | 备注  |
| sku      | name     | quantity | unitPrice | note  |
|----------|----------|----------|-----------|-------|
| PRD-001  | 螺丝钉   | 500      | 0.50      | 采购  |
| PRD-002  | 轴承     | 20       | 35.00     | 补货  |

Rules:
- SKU is required and used to match/create Product
- Rows with missing SKU → skip and log as error
- Rows with invalid quantity (<=0 or non-numeric) → skip and log
- All valid rows processed in one DB transaction (all or nothing per row)
- Return detailed error report per failed row
